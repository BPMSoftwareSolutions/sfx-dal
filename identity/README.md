## Login foundation

The identity DAL is generated by CodeLightly from the live **sfx-identity** database.
It has its own project, namespace, assembly and connection, separate from the
estate DAL. Its process setting is SFX_IDENTITY_CONNECTION_STRING, configured on
Azure App Service sidefx, slot staging.

The initial catalog inspection on 2026-10-03 had VIEW DEFINITION permission and
counted zero tables, procedures, views and functions. The paired
[identity migration](sql/migrations/001-login-identity.commit.sql) installs the
minimum persistence for the four CLI login providers. It creates no users or
passwords. It was preflighted with rollback, installed, and reapplied to check
idempotence. No SDA Kernel, estate capability, HTTP endpoint or deployment changed.

## Generated surface

| Stored procedure | Private responsibility |
| --- | --- |
| identity.begin_authentication_attempt | Shared account/source throttling and bounded attempt lifetime |
| identity.resolve_login_principal | Indexed realm/identifier lookup, attempt-bound principal/version snapshot |
| identity.read_password_verifier | Credential provider only; current verifier for the resolved attempt |
| identity.complete_credential_verification | Trusted verifier records one accepted/rejected result and audit |
| identity.establish_session | Consumes successful verification and rechecks account/credential versions atomically |
| identity.validate_session | Hash lookup; absolute/idle expiry, revocation and account/version checks |
| identity.revoke_session | Idempotent revocation by session hash |
| identity.provision_principal_credential | Operator-only enrollment with an already-derived Argon2id verifier |

All eight procedures have generated typed result models and synchronous/asynchronous
repositories. Seven base tables also receive generated models/repositories:
principal, password_credential, authentication_attempt, authentication_throttle,
session, authentication_audit and login_policy. There are no application
views/functions or references to legacy estate views.

Generated files under Models, Interfaces, Repositories, Helpers and Procedures,
plus SFX.Identity.DAL.csproj and catalog-manifest.v1.json, must not be edited by
hand. Change database declarations, regenerate and rebuild consumers.
Configuration, SQL, documentation, regenerate.ps1 and verification receipts are
maintained source. Root Directory.Build.props excludes the identity project and
operator tools from the estate project's recursive compilation.

The [provider adapter](../../sfx-providers/providers/cli-login/GeneratedIdentityDal.cs)
calls specific generated repositories. It never routes a user-supplied procedure
name through the public procedure-extract API. Identity procedures must not enter
that API's allowlist.

## Regenerate

Prerequisites: .NET 8 or newer, the existing CodeLightly checkout, and the dedicated
connection setting in this process. No credential belongs in config, command
arguments, generated code, Git or verification output.

An Azure administrator can load the existing staging setting without printing it.
Run from the sfx-dal repository:

~~~powershell
$env:SFX_IDENTITY_CONNECTION_STRING = az webapp config appsettings list --name sidefx --resource-group sidefx_group --slot staging --query "[?name=='SFX_IDENTITY_CONNECTION_STRING'].value | [0]" --output tsv
try {
  ./identity/regenerate.ps1 -CodeLightlyRoot '<CodeLightly checkout>' -ReceiptPath identity/verification/generation.json
} finally {
  Remove-Item Env:\SFX_IDENTITY_CONNECTION_STRING
}
~~~

The script inspects the target and refuses database/source procedure drift before
running CodeLightly. SQL Server's CREATE OR ALTER header normalization is accounted
for; the rest of each procedure body must match exactly. When introducing a new
migration generation, update that declared migration source in regenerate.ps1.
The script requires a typed model for each
configured procedure, builds the assembly, verifies manifest file hashes and
optionally records generator/config/SQL/DLL digests. It never installs SQL.
The config uses Process in Debug and Release, with no fallback to the estate's
machine setting. Set the environment before first repository use; the generated
connection helper caches it for that process.

~~~powershell
dotnet restore identity/SFX.Identity.DAL.csproj --locked-mode
dotnet build identity/SFX.Identity.DAL.csproj -c Release --no-restore
~~~

## Database lifecycle

The operator tool selects only the known identity inspection/migration files,
checks the database name, suppresses secret-bearing error messages and never
opens an outer transaction. With the same process setting:

~~~powershell
dotnet run --project tools/identity-database -c Release -- inspect identity identity/verification/schema.json
dotnet run --project tools/identity-database -c Release -- preflight identity identity/verification/preflight.json
dotnet run --project tools/identity-database -c Release -- install identity identity/verification/install.json
~~~

Preflight applies the rollback twin and runs the
[database contract assertions](sql/verify-login-contract.sql) in that uncommitted
transaction. Its throwaway verifier-shaped value tests persistence contracts only.
Real Argon2/password verification is exercised by the live provider tests.
Install runs the commit twin exactly as authored. The twins differ only in their
terminal transaction action. Inspect/review differences before applying to an
existing schema; the initial migration is additive and does not silently reconcile
changed table definitions.

sfx_identity_runtime receives EXECUTE on the seven login/session procedures,
DENY on direct table reads/writes, and DENY on enrollment.
sfx_identity_enrollment receives enrollment EXECUTE and no direct table access.
No login/user is automatically added to either role. An appropriately scoped
application database principal remains a deployment task; an administrator's
connection is not evidence of application least privilege.

The trusted service supplies the realm and derives source_key from trusted
ingress. The database normalizes identifiers and uses the principal PK as the
existing-account throttle identity. Unique indexes and PK/FK joins resolve
principals, attempts, credential versions and session hashes.

Initial policy is declared in login_policy: 120-second attempts, 1800-second
absolute sessions, 900-second idle sessions, and 5 account / 25 source attempts
per 300-second window. SQL clamps requested expiry. Raw passwords and session
bearers are never persisted. Session hashes are SHA-256 of 32 random token bytes;
password checking stays in the provider. Credential rotation/recovery, audit
retention and expired-row cleanup procedures are subsequent work; enrollment is
create-only.

## Evidence and limits

[Generation receipt](verification/2026-10-03-generation.json),
[live schema/PK/FK/signature/body hashes](verification/latest-schema.json),
[rollback preflight](verification/2026-10-03-preflight.json) and
[live provider checks](verification/2026-10-03-live-providers.json) record this
generation. The initial empty catalog and post-rollback catalog are retained too.

Live checks cover actual password login, rejection, disabled users, concurrent
database verification/session consumption, version changes, throttling,
expiry/revocation and actual denied operations under the runtime role.
Test principals, credentials, attempts and sessions are deleted by their unique
test realm. Anonymous throttle audit events and counters remain as execution
evidence; counters become eligible for reset after their window, rather than
being automatically deleted.

No real account is enrolled. API/CLI wiring, host deployment, real Windows/macOS
terminal acceptance, estate admission and private circuit observation are not
established by these tests. Generated methods currently lack cancellation
parameters; the adapter awaits actual completion and honors cancellation
before/after a call, without claiming cancellation rolls back committed writes.
